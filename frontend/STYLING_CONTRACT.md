# Frontend Styling Contract

## Ownership Map
- **Tailwind + daisyUI (`frontend/css/tailwind.input.css`)**:
  - Design tokens (`@theme`, `@layer base :root`)
  - Generic primitives (`btn`, `badge`, `input/select/textarea`, alerts, progress)
  - Premium layout primitives (`panel`, `panel-primary`, `panel-quiet`, `analytics-panel`)
  - Product primitives (`metric-card`, `action-card`, `active-pill`, `eval-pill`, `quality-pill`, `catalog-card`)
  - Workspace primitives (`workspace-hero`, `hero-banner`, `filter-bar`, `split-analysis-layout`, `wizard-shell`, `wizard-stepper`, `stepper-rail`)
  - Chess UI shells (`board-stage`, `engine-panel`, `engine-eval-bar`, `mini-board-thumb`, `mastery-bar`, `board-arrow`, `promotion-overlay`)
  - Tap-target classes: `.tap-40`, `.tap-44` — replaces `min-h-[40px]` / `min-h-[44px]` literals.
  - Typography classes: `.tracking-kicker` (0.08em), `.tracking-label` (0.12em), `.auth-kicker` (0.16em), `.hero-display` (32px/1.05/700), `.text-2xs` (11px) — replace inline arbitrary values.
  - Mobile bottom-nav: `.bottom-nav-item`, `.bottom-nav-label`, `.bottom-nav-badge` (gated by `@media (max-width: 640px)` inside `tailwind.input.css`).
  - Auth + onboarding chrome: `.auth-card`, `.skip-link`, `.coach-pane`, `.coach-input-tall`.
  - Dashboard chrome: `.dashboard-secondary` (collapses under `body.dashboard-focused`).
  - Most layout, spacing, typography, and responsive behavior (`max-sm`, `max-md`, etc.)
- **Lit web components (`frontend/js/components/*.js`)**:
  - Declarative primitives consumed by views via custom elements (`<cc-empty-state>`, `<cc-skeleton>`, …).
  - Light DOM by design — Tailwind/daisyUI utility classes still apply inside the component.
  - Side-effect imports in `frontend/js/app.js` register the elements globally.
  - APIs documented in `frontend/design/COMPONENT_CONTRACTS.md`. Adding a new component requires updating that file.
- **Custom runtime CSS (`frontend/css/app.css` imports)**:
  - `layout.css`: behavior/state hooks only (sidebar collapsed, focus and OS reduced-motion behavior)
  - `features.css`: chess-domain visuals and interaction semantics only (board, pieces, drag visuals, heatmap)
  - `responsive.css`: residual responsive exceptions only
- **Design tokens (`frontend/design/`)**:
  - `tokens.json` is the single source of design truth (RN-shape).
  - `theme.ts` is generated by `node frontend/design/build-tokens.mjs` and consumable by a future React Native port.
  - The `:root` block in `tailwind.input.css` currently mirrors `tokens.json`; if you change one, change the other.
- **Removed legacy stubs**:
  - `frontend/css/modules/components.css`
  - `frontend/css/modules/views.css`
  - `frontend/css/modules/tokens.css`
  - These were retired after the stable-cycle checkpoint; do not recreate.

## When To Add Custom CSS
Add custom CSS only if **both** are true:
1. Tailwind/daisy composition cannot express the behavior cleanly, and
2. The rule is chess-domain specific or one of the allowed responsive residuals.

If the style is generic UI (card spacing, headings, badges, button variants, empty/loading/error wrappers), keep it in utility/daisy composition or as a Lit primitive, not in residual CSS modules.

Aceternity-style glow/elevation effects are implemented locally in `tailwind.input.css`. Do not add an Aceternity dependency unless the project explicitly needs a specific upstream component.

## Frontend Gate (`npm run frontend:gate`)

The audit script lives at `scripts/frontend_migration_audit.py` and enforces five rules. All five must pass before merging frontend styling changes.

1. **`app.css` imports are minimal.** Only `layout.css`, `features.css`, `responsive.css` allowed.
2. **Tailwind `@source` coverage** includes `index.html`, `js/**/*.js`, `js/modules/ui.js`, `js/modules/views/**/*.js`, and `js/components/**/*.js`. Missing entries fail.
3. **Primitive ownership.** Each known primitive (`btn`, `card`, `coach-bubble`, etc.) has exactly one definition in `tailwind.input.css` and is not redefined in residual modules.
4. **Runtime allowlist** declares the domain-specific classes each residual module is permitted to own.
5. **Inline-Tailwind cap.** Counts arbitrary-value classes in HTML templates that don't reference design tokens (e.g. `text-[13px]`, `gap-[6px]`, `bg-[linear-gradient(...)]` are flagged; `text-[var(--muted)]` and `rounded-[calc(var(--radius)+4px)]` are token-using and excluded). The cap moves down only — never up. Current cap: 25; current count: 22. Trajectory across H4–H14: 165 → 22.

Run the gate:

```bash
npm run frontend:gate
```

If you must add an arbitrary-value class, ask first: can it be a token-using `[var(--…)]` reference, an existing extracted class, or a new design-system class? In that order. Lowering the cap is a quick win whenever a natural class extraction presents itself.

## Color Discipline

The dark theme has three saturated colors at near-equal weight: `--primary`
(green), `--info` / `--blue` (#58a6ff), and `--analytics` (#a855f7). When all
three appear in the same view at similar saturation they fight for attention
and the screen reads "dashboard" instead of "premium product."

Rules going forward:

- **Green = action.** Primary CTAs, active nav state, "improving" trend
  arrows, drill-correct feedback, success badges. If something is green in
  the UI chrome, it should mean "do this" or "this got better."
- **Blue and purple are data-vis only.** Use them inside chart series,
  heatmap legends, and the analytics surface (`.analytics-panel`,
  trend-deltas, opening genome). Avoid them on buttons, pills, status
  text, or border accents.
- **Errors and warnings stay semantic.** Use `--error` and `--warning`;
  do not improvise red/amber accents.
- **Neutral grays carry density.** When in doubt, reach for `--muted`,
  `--faint`, or `--surface-2` before a saturated accent.

Existing primitives already follow this — `.active-pill`, `.quality-pill`,
`.btn-primary`, `.tap-44` active states, drill-feedback green flashes. The
discipline applies to new code, not a bulk recolor.
